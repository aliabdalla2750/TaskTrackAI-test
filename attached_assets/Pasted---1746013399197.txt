إدارة العملاء المرتبطين بالمشاريع داخل الوكالة، مع إمكانية تقييمهم، متابعة حالة الدفع، عرض المشاريع السابقة، والتواصل السريع معهم.

📄 الصفحة الأساسية:
/dashboard/agency/clients

✅ محتويات صفحة العملاء:
العنصر	التفاصيل
🔠 اسم العميل	اسم ظاهر بوضوح – يفضل مع Initials أو صورة بسيطة
📁 عدد المشاريع	مثل: "3 مشاريع نشطة – 2 مكتملة"
💰 حالة الدفع	✅ منتظم / ⚠️ متأخر / ❌ متوقف (بناءً على سجل الدفع)
⭐ تقييم داخلي	1 إلى 5 نجوم (يظهر للإدارة فقط)
💬 زر تفاصيل العميل	ينقل إلى /dashboard/agency/clients/:clientId
💬 زر تواصل واتساب	يفتح رابط مباشر عبر wa.me
📄 صفحة تفاصيل العميل
/dashboard/agency/clients/:clientId

تحتوي على:
🧾 بيانات العميل الأساسية:

الاسم + البريد + رقم الهاتف

📂 المشاريع المرتبطة:

جدول يوضح اسم المشروع – الحالة – التاريخ – المسؤول عنه

💳 سجل الفواتير:

جدول فيه الفاتورة – القيمة – الحالة (مدفوعة / متأخرة)

🧠 التقييم الداخلي:

شريط من 5 نجوم

ملاحظات إدارية داخلية (غير ظاهرة للعميل)

📝 زر "كتابة ملاحظة داخلية":

يفتح TextArea لإضافة تعليق إداري (زي: "يتأخر في الرد" أو "يتفاوض بقوة")

🔁 Workflow المقترح:
عند إنهاء المشروع:
تظهر رسالة في صفحة /projects/:projectId:

"هل ترغب في تقييم هذا العميل؟ ⭐"

يتم تعبئة:

التقييم النجمي.

تعليق داخلي (اختياري).

يتم حفظ التقييم داخل client_feedback أو داخل جدول clients.

📦 قاعدة البيانات المقترحة:
clients
الحقل	النوع
id	UUID
name	String
email	String
phone	String
agency_id	FK
rating	Integer (1-5)
internal_notes	Text
projects
| client_id | FK | لكل مشروع عميل |

payments
| client_id | FK | لحساب سجل الدفع للعميل |

🔔 تنبيهات ذكية (مقترحة لاحقًا):
الحالة	التنبيه
العميل عنده أكثر من فاتورة متأخرة	"⚠️ العميل X تأخر في 3 دفعات متتالية"
العميل تم تقييمه بأقل من 3	"🟠 العميل مصنف كـ صعب التعامل"
🧪 حالات اختبار مهمة:
الحالة	النتيجة المتوقعة
حذف عميل	غير مسموح إذا كان له مشاريع نشطة
تقييم مكرر لنفس المشروع	ممنوع – يسمح بتعديل التقييم السابق
كتابة ملاحظات داخلية	تظهر فقط للإدارة – ولا يتم إرسالها للعميل
🎨 تحسين واجهة صفحة العملاء:
استخدم كروت ملونة لكل عميل مع حالة الدفع.

ضف رموز واضحة لحالة التفاعل (👍 جيد – 🔄 متوسط – ⚠️ خطر).

فلترة حسب عدد المشاريع، أو حسب مستوى التقييم.
