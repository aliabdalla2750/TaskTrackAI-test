أريد التأكد من أن جميع صفحات النظام والوظائف (features) تعمل بشكل كامل بدون الحاجة لتفعيل نظام تسجيل الدخول أو صلاحيات المستخدمين (roles)، لكن مع الحفاظ على ترابط البيانات الداخلي الحقيقي بين كل الصفحات، بحيث التغييرات التي تتم في صفحة مثل "لوحة تحكم الأدمن" تظهر مباشرة في "لوحة تحكم الوكالة" أو "الموظف".

🧱 الفرضيات الحالية:

لا يوجد تسجيل دخول (authentication).

لا يوجد فصل بين أنواع المستخدمين (client/agency/admin/employee).

النظام يعمل كـ Demo Session واحدة لتسهيل التطوير.

📌 ما أحتاجه تحديدًا:

كل صفحة في النظام يجب أن تكون مفتوحة وقابلة للاستخدام المباشر من غير أي Login.

كل عملية إدخال أو تعديل في أي صفحة، يجب أن تُربط داخليًا بـ default IDs ثابتة لضمان الترابط.

🔧 🧩 القيم الثابتة المطلوبة في الكود (لـ الربط المنطقي):
js
Copy
Edit
// env.ts أو ملف ثابت داخلي
export const defaultAgencyId = "demo_agency";
export const defaultAdminId = "demo_admin";
export const defaultClientId = "demo_client";
export const defaultEmployeeId = "demo_employee";
🛠️ ما يجب تنفيذه:
1. عند إنشاء مشروع:
يجب أن يتم ربط المشروع بـ:

agency_id = demo_agency

created_by = demo_admin

client_id = demo_client

2. عند إنشاء مهمة:
ترتبط بـ:

project_id

assigned_to = demo_employee

3. عند إنشاء فاتورة:
ترتبط بـ:

project_id

client_id = demo_client

agency_id = demo_agency

4. عند توليد تقرير أو تسجيل Standup:
يتم تسجيله بـ:

employee_id = demo_employee

agency_id = demo_agency

5. أي صفحة تعتمد على Fetch API:
يجب أن تُفلتر البيانات باستخدام القيم السابقة تلقائيًا.

مثال: /projects?agency_id=demo_agency

مثال: GET /tasks?assigned_to=demo_employee

🧪 حالات يجب اختبارها:
الحالة	التحقق المطلوب
إنشاء مشروع من صفحة الأدمن	يظهر تلقائيًا في صفحة الوكالة
إنشاء فاتورة من داخل مشروع	تظهر في صفحة الفواتير والـ Wallet
تسليم مهمة	يظهر أثرها في التقارير اليومية
إنشاء تقرير أسبوعي	يُرسل بناءً على المهام الفعلية للمشروع
أي تغيير في مشروع/مهمة	يظهر عبر كل صفحات النظام المرتبطة
🎨 المطلوب في الواجهات:
لا تطلب Login.

لا تمنع دخول أي صفحة.

كل صفحة تفترض أنك تعمل لحساب demo_agency.

📌 ملحوظة مهمة:
عند الانتهاء من جميع الميزات، سيتم لاحقًا بناء نظام تسجيل دخول وتوزيع الصلاحيات. لكن الآن، الهدف هو التأكد من أن كل الفيتشرز شغالة فعلًا ومترابطة على مستوى البيانات، مش مجرد ديمو أو فصل صفحات.
